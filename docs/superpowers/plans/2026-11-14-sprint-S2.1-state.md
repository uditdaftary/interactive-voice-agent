# Sprint S2.1: one session state machine, deadlines and tracked tasks. Implementation plan

> **For agentic workers:** follow the orchestration protocol in `docs/superpowers/plans/2026-11-13-remediation-roadmap.md`. Steps use checkbox (`- [ ]`) syntax.

**Goal:** One object owns the session state, refuses illegal transitions, broadcasts every change from one place, and never leaves the agent stuck in `LISTENING` or in a silent `NARRATING`. Every background task is tracked, logged on failure and cancelled at shutdown.

**Architecture:**
- `SessionState` in `orchestrator/state_machine.py` holds `state`, `resume_to`, the legal transition table and the `LISTENING` deadline, and notifies listeners on each change.
- `ConnectionManager` stops storing state; it exposes `session` and keeps `state` as a read-only delegate so the many readers don't churn.
- `TaskRegistry` in `server/tasks.py` replaces every bare `asyncio.create_task`.
- One listener broadcasts `state_sync`; one disarms the accumulator on leaving `LISTENING`; the engine's listener cancels its tasks on entering `PAUSED`.

**Tech stack:** asyncio (`loop.call_later` for the deadline), FastAPI lifespan.

**Spec:** section 5.1 and section 8 (P2 bullet: deadline extended while `is_speaking`). Matrix: M4, M6, L5, the state part of L6, and the deadline half of M11.

## Review focus
1. The deadline must never fire while the user is speaking or while an utterance is with STT, and must not fire after the state already left `LISTENING` (a stale timer).
2. Entering `PAUSED` from any state cancels narration, reply and STT tasks, and a cancelled caller sees `CancelledError` (nothing swallows it).
3. A narration-loop exception (TTS raises) ends in `PAUSED` with an error broadcast, not a silent `NARRATING`.
4. The last client disconnecting pauses; a reconnect sees `PAUSED` in `state_sync` and the HUD shows it.
5. `state_sync` is broadcast exactly once per transition, from the listener, and never from a thread other than the loop.

### Task 1: `SessionState` with legal transitions and `resume_to`

**Files:**
- Modify: `src/voice_agent/orchestrator/state_machine.py`, `src/voice_agent/settings.py`
- Test: `tests/test_session_state.py`

**Interfaces:**
- `SessionStateName = Literal["NARRATING", "PAUSED", "LISTENING", "REPLYING"]`.
- `class SessionState`:
  - `__init__(self, *, listen_deadline_s: float, followup_window_s: float)`; initial `state = "PAUSED"`, `resume_to = "PAUSED"`.
  - `state` and `resume_to` read-only properties.
  - `def transition(self, to: SessionStateName, reason: str) -> bool`. Legal edges, exactly spec 5.1:
    - `NARRATING|PAUSED -> LISTENING`
    - `NARRATING|PAUSED|LISTENING|REPLYING -> REPLYING`
    - `LISTENING -> resume_to`, `REPLYING -> LISTENING`, `REPLYING -> resume_to`
    - any `-> PAUSED`; `PAUSED -> NARRATING`.
    - Leaving `NARRATING` or `PAUSED` sets `resume_to` to the state left. A same-state transition is a no-op returning True without notifying (except `REPLYING -> REPLYING`, which notifies with the reason so a new reply can replace the old one).
    - An illegal edge logs one WARNING `"illegal transition %s -> %s (%s)"` and returns False.
  - `def resume(self, reason: str) -> bool`: shorthand for `transition(self.resume_to, reason)`.
  - `def add_listener(self, fn: Callable[[str, str, str], None]) -> None`, called as `fn(old, new, reason)` after each change, in registration order. A listener exception is logged with traceback and does not stop the others.
- All calls happen on the event loop; document that in the class docstring. No lock.

### Task 2: the `LISTENING` deadline

**Files:**
- Modify: `src/voice_agent/orchestrator/state_machine.py`
- Test: `tests/test_session_state.py` (extend)

**Interfaces:**
- `def enter_listening(self, reason: str, *, followup: bool = False) -> bool`: transitions to `LISTENING` and arms the deadline (`followup_window_s` if `followup`, else `listen_deadline_s`) with `asyncio.get_running_loop().call_later`.
- `def extend_deadline(self) -> None`: while in `LISTENING` and not suspended, re-arms the deadline to the full duration it was armed with. The caller invokes it whenever the accumulator reports `is_speaking`.
- `def suspend_deadline(self) -> None` / `def resume_deadline(self) -> None`: while suspended the timer is cancelled; resume re-arms the full duration. (S2.2 calls these around STT.)
- Expiry: if still in `LISTENING` and not suspended, `resume("deadline")`. Any transition out of `LISTENING` cancels the timer, so a stale timer never fires.
