# Sprint S4.2: optional Pocket TTS and Moonshine STT backends; delete the vendored workers. Implementation plan

> **For agentic workers:** follow the orchestration protocol in `docs/superpowers/plans/2026-11-13-remediation-roadmap.md`. Steps use checkbox (`- [ ]`) syntax.

**Goal:** The two optional local backends work behind the S3.2 protocols, install only through extras, and the vendored game-mod TTS workers are gone.

**Architecture:**
- `tts/backends.py` gains `PocketTtsBackend` (`name = "pocket"`), selectable as `tts_primary`.
- `stt/backends.py` gains `MoonshineBackend`, which runs `stt/local_stt_worker.py` as a child process and speaks its JSON-lines protocol; Whisper stays the default.
- Both import their libraries lazily, so the base install and CI never need them.

**Tech stack:** `pocket-tts` (Kyutai), `sherpa-onnx` for Moonshine, `asyncio.create_subprocess_exec`.

**Spec:** sections 5.5 (MoonshineBackend) and 5.6 (PocketTTSBackend), section 4 (delete OmniVoice and the vendored workers). Matrix: H9.

## Review focus
1. Pocket loads once, on CPU, off the event loop, and caches one voice state per voice id; a missing voice WAV falls back to the default voice with a WARNING, not a crash.
2. Pocket synthesis is cancellable between chunks: cancelling the awaiting task stops generating within one chunk.
3. The Moonshine child process is started once, reused, killed on shutdown, and restarted after it dies; a hung worker can't block the event loop (timeouts on reads).
4. Moonshine output passes the same speech judge path as Whisper (the worker already judges; the backend maps its `speech: false` / empty finals to a `rejected_reason`).
5. With neither extra installed, `import voice_agent.tts.backends` and `voice_agent.stt.backends` succeed and the default suite passes.

### Task 3: `MoonshineBackend`

**Files:**
- Modify: `src/voice_agent/stt/backends.py`, `src/voice_agent/settings.py`, `pyproject.toml` (extra)
- Test: `tests/test_moonshine_backend.py`

**Interfaces:**
- `Settings.stt_backend: str = "whisper"` (env `VOICE_AGENT_STT_BACKEND`, accepted `"whisper" | "moonshine"`, validated at load like `tts_primary`) and `Settings.moonshine_model_dir: str = "models/stt/moonshine-tiny-en-int8"`.
- `class MoonshineBackend` implementing `SttBackend.transcribe(pcm16, sample_rate) -> Transcript` (synchronous, like Whisper; callers already run it in a thread):
  - starts `sys.executable <path to local_stt_worker.py> --model <dir> --kind moonshine` once with `subprocess.Popen` (pipes, text mode), waits for `{"type":"ready"}` within 30 s;
  - sends the request objects the worker's protocol defines (read its module docstring for the exact request shape) and reads lines until the matching `final` or `error`, with a 30 s read timeout;
  - maps `final` with `speech: false` or empty text to `Transcript("", "not-speech")`, `error` to `Transcript("", "stt-error")` with a WARNING, and a dead or timed-out worker to `Transcript("", "stt-unavailable")` after killing it (the next call restarts it, with the same 30 s cooldown rule as Whisper);
  - `close()` kills the process; registered with `atexit`.
- `_construct_stt_engine` (in `server/app.py`) is S2.1's file this sprint; instead add `def build_stt_backend(settings: Settings) -> SttBackend` in `stt/backends.py` and leave the server wiring to S3.3. Say this in the PR.
